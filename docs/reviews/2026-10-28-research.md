# Tableau.Api research: features and modernization, 2026-10-28

> Written on 2026-10-28 and kept with the private review until Tableau.Api 1.2.6 shipped on 2026-10-30. A dated record, never current truth: the plan, `docs/plans/2026-10-28-modernization.md`, records which recommendations were taken.

What the next major release of Tableau.Api should deliver, and in what order. It draws on four inputs:

- the repo at `D:\workspaces\Tableau.Api` (commit `4267562`), read but not built;
- the Tableau REST API reference and help pages on help.tableau.com, read on 2026-10-28;
- Microsoft Learn, nuget.org and GitHub for .NET practice, packaging and the ecosystem;
- the official xsd files `ts-api_3_16.xsd` and `ts-api_3_29.xsd`, downloaded and compared.

A separate agent reviews the code line by line. This report covers only what faces outward: the API, the platform and
the ecosystem. It names code defects only where they change a recommendation.

Claims marked *(verify)* were not confirmed against a primary source. Each must be checked before a plan relies on it.

## Where the package stands

- **What nuget.org ships:**
  - `Tableau.Api` 1.2.5, published 2021-10-13;
  - 70,546 downloads in total, 12,719 of them for 1.2.5, about 23 a day;
  - owners `serionist` and `Starschema`;
  - target `netstandard2.0`, one dependency (`Microsoft.Extensions.Logging >= 2.1.1`);
  - no licence;
  - its description still says "All versions and endpoints are supported up to 2018.2".
- **What `main` holds but never shipped:**
  - a retarget to `netstandard2.1` (2023-05), which drops .NET Framework;
  - the whole Vizportal client (31 methods), written in 2023, mostly by László Nemes, plus Newtonsoft.Json to serve
    it. The 1.2.5 assembly has no Vizportal types;
  - an xsd regenerated from 3.16 (Tableau Cloud June 2022) in 2022-08, although `_maxVersion` still caps every request
    at `/api/3.14/` (Server 2021.4).
- **The code itself:**
  - 142 public REST methods across 14 partial files;
  - models generated by `xsd.exe` into one 11,158-line `XmlSchema.cs`, serialized with `XmlSerializer`;
  - IL2026 and IL2104 already in `NoWarn`;
  - a new `HttpClient` and handler on every request;
  - the session passed as a `TableauSession` argument to every call;
  - `CancellationToken?` parameters.
- **Tests:** `netcoreapp2.1`, MSTest 1.2.1, and only live tests that need a server.
- **The GitHub repo:**
  - `github.com/serionist/Tableau.Api` was created and made public today, 2026-10-28;
  - it has no licence;
  - its description advertises "the Vizportal API".
- **The market:**
  - no maintained, general-purpose .NET client covers today's REST API (Q7);
  - Tableau's own .NET offerings are the Migration SDK, which serves a single purpose, and the Hyper API, which is
    deprecated.

**Latest version.** REST API **3.30** ships with Tableau Cloud October 2026 and Tableau Server 2026.3. Each Tableau

- **The release cycle changed in 2026.** Until 2025, every other version was Cloud only. Since 2026.1, every version
  ships on both Server and Cloud, three times a year.
- **Versioning by resource.** The newer endpoints sit under `/api/-/` with no number in the path: Pulse, Collections,
  Content Exploration, Identity Pools, Knowledge Graph and others. On Tableau Cloud, compatible changes land in the
  current endpoint version, and a resource's version moves only when it breaks. A client therefore needs two URL
  shapes, `/api/{version}/...` and `/api/-/...`.
- **The URI takes major.minor only**, for example `3.29`. Schema versions can carry an update number.

The schema grew from 191 named types in 3.16 to 296 in 3.29: 105 added and none removed.

**Deprecated or retired since 3.16:**

- **Ask Data lenses:** retired in 3.22. All five lens methods, and lens permissions, are gone.
- **Legacy Metrics:** retired in 3.22 (Get, List, Update, Delete, Get Metric Data, Add Metric to Favorites). Pulse
  replaces them.
- **Dashboard Extensions Settings:** retired in 3.21. Tableau Extensions Settings replace them.
- **Data Acceleration:** methods and attributes retired in 3.29.
- **Add Flow Task to Schedule:** retired on Cloud in March 2024. On Server it lives on as "Add Flow Task to Server
  Schedule"; on Cloud, Create Cloud Flow Task (3.22) replaces it.
- **View recommendations:** Get, Hide and Unhide were deprecated in 3.19.
- **`queryTaggingEnabled`:** deprecated in 3.23.
- **Pulse:** Batch list metric definitions (few) was deprecated in 3.24.
- **Embedding scopes:** `tableau:metrics:embed` and `tableau:ask_data:embed` are retired.
- **Tableau Cloud schedules:** Cloud no longer uses shared server schedules. Since 3.20, Create and Update Cloud
  Extract Refresh Task, and Cloud subscriptions, carry their own frequency, in five-minute steps. Server schedule
  methods are marked "Server only".

The client calls none of the retired methods. Its schedule and subscription methods, though, use only the Server form,
so on Tableau Cloud they fail or send the wrong payload.

**Where to download the xsd.** The "REST API XML Schema" page lists one file per version at
`https://help.tableau.com/samples/en-us/rest_api/ts-api_<major>_<minor>.xsd`.

- The newest listed today is `ts-api_3_29.xsd` (160,752 bytes).
- `ts-api_3_30.xsd` returned 404 on 2026-10-28, although 3.30 has shipped. Schema files can trail the release.

**JSON.**

- **It is supported.** The Fundamentals page says requests may be XML or JSON, and the response follows the `Accept`
  header. If `Accept` is sent, it must match `Content-Type` (`application/json` or `application/xml`). XML is the
  default.
- **Some endpoints are JSON only:**
  - Pulse;
  - the `/api/-/` OpenAPI-style endpoints *(verify per endpoint)*;
  - Update Data in Hyper Data Source, whose `actions` body is JSON;
  - the Metadata API (GraphQL);
  - VizQL Data Service;
  - the Tableau Cloud Manager API.
- **Some are documented in XML only:** the `request_payload` part of a multipart publish. Whether it also accepts JSON
  is *(verify)*.
- **No schema covers the JSON.** It is the XML converted mechanically, per the docs' note about the Jackson parser.
  - Attributes become properties, and lists keep their wrapper objects, for example `{"users":{"user":[...]}}`
    *(verify)*.
  - Numbers such as `totalAvailable` arrive as strings *(verify)*.
  - The xsd remains the only formal contract.

**Is JSON the better wire format for a modern client?** Yes, for this client:

- the System.Text.Json source generator makes the library trim- and AOT-safe, and `XmlSerializer` cannot (Q5);
- every API Tableau has added since 2021 is JSON;
- one serializer can cover REST, Pulse, Metadata GraphQL and VizQL Data Service.

The cost:

- the JSON shape is undocumented, so it must be pinned with fixtures recorded from a live site (Q6);
- the multipart publish payload stays XML, written with `XmlWriter`, which is AOT-safe;
- TSC and Tableau's own Migration SDK both stay on XML (Q7), so fewer people have tested the JSON path.

### Q3. Authentication on Server and Cloud now

| Method | Server | Cloud | Limits that shape the client |
|---|---|---|---|
| Username and password | Yes | Only without MFA; never with SSO | Since 2022-02-01, MFA is a contractual requirement on Cloud, so with Tableau authentication the REST sign-in needs a PAT or a UAT. Repeated bad credentials return 401001, login blocked |
| Personal access token | Yes | Yes | One session per PAT: a new sign-in ends the previous session, even on another site. A PAT unused for 15 days expires. Server: 1-year lifetime (`refresh_token.absolute_expiry_in_seconds`), 10 PATs per user. Cloud: lifetime set by the site admin (180 days, or 1 to 365), 104 PATs per user. Sign-in returns `estimatedTimeToExpiration` |
| Connected app, direct trust | Yes (3.17) | Yes (3.16) | A JWT signed HS256 with the app's secret. Header `kid` (secret id) and `iss` (client id). Claims `iss`, `exp` (at most 10 minutes), a unique `jti`, `aud` = `tableau`, `sub` = username, and `scp` as an array (never `scope`). At most two secrets per app; secrets do not expire. Sign In and Sign Out need no scope since 3.20 (Cloud) and 3.21 (Server) |
| Connected app, OAuth 2.0 trust (EAS) | Yes (3.23) | Yes (3.16) | Same `jwt` sign-in, but the customer's identity provider issues the JWT, and Tableau trusts its keys |
| Unified access token | No | Yes (3.27, December 2025) | A JWT signed with the customer's key (RS256 suggested, `kid` needed with a JWKS URI). Claims `iss`, `exp`, `iat`, `https://tableau.com/tenantId` and a username claim. Configured through the Tableau Cloud Manager API, which itself needs a TCM PAT. Sign in with `isUat="true"`. Concurrent sessions are allowed |
| Impersonation | Yes | No | A server administrator signs in (password, or a PAT once `tsm authentication pat-impersonation enable` is set, Server 2021.1 and later) and adds `<user id="...">`. On Cloud, the only way to act as another user is a JWT whose `sub` is that user |

- **Session lifetime.**
  - Server: a credentials token lasts about 240 minutes, set by `wgserver.session.idle_limit`.
  - Cloud: 120 minutes, or 30 idle minutes (UAT page).
  - A token is valid only for its own site.
  - Sign Out invalidates the token. Since 3.27, Sign Out also ends direct-trust sessions on Cloud.
- **Scopes.**
  - The format is `tableau:<resource>:<action>`, with `*` allowed in the action position, for example
    `tableau:projects:*`.
  - The reference lists each method's scope. A method that lists none cannot be called with a JWT.
  - The Metadata API accepts only `tableau:content:read`.

**What a modern client should support:**

- **Credentials:**
  - all four sign-in methods (password, PAT, connected app JWT, UAT) through one credentials abstraction;
  - for the JWT kinds, a delegate that mints a fresh JWT at each sign-in, because `exp` is at most 10 minutes and
    `jti` must be unique.
- **One session manager:**
  - per configured client, a singleton, not the transient typed client;
  - signs in lazily on the first call;
  - caches the token, site LUID and user LUID;
  - signs in again once on 401 or on known expiry;
  - single-flight: one sign-in at a time behind a `SemaphoreSlim`. A PAT allows one session, so two parallel sign-ins
    end each other's sessions;
  - signs out on `DisposeAsync`.
- **An explicit session API** for callers who manage sites themselves: multi-site jobs, Switch Site, impersonation.
  This keeps today's `TableauSession` model as an option.
- **Guarding Server-only methods** (impersonation, Switch Site) with a typed error before any request is sent, never
  after a 4xx.

Proposed shape (illustrative):

```csharp
services.AddTableauClient("prod", o =>
    {
        o.ServerUrl = new Uri("https://prod-useast-a.online.tableau.com");
        o.SiteContentUrl = "marketing";
        o.ApiVersion = TableauApiVersion.Negotiate;   // or a pinned "3.27"
    })
    .UsePersonalAccessToken(sp => sp.GetRequiredService<ISecretStore>().GetPat("tableau"))
    // .UseConnectedAppJwt((ct) => jwtFactory.CreateAsync(user, scopes, ct))
    // .UseUnifiedAccessToken((ct) => uatFactory.CreateAsync(ct))
    // .UsePassword(name, password).Impersonate(userLuid)   // Server only
```

### Q4. Vizportal

**What it is.** Vizportal is the internal JSON-RPC API behind the Tableau web UI, at
`/vizportal/api/web/v1/{method}`. The client:

- puts the REST token in a `workgroup_session_id` cookie, with a generated `XSRF-TOKEN` cookie and header;
- addresses content by integer id, not LUID.

**Is it still used?** The web UI uses it. Third parties have worked from community write-ups since 2016-2017
("vizibly diffrnt", pyvizpo, which was tested only on Tableau 10). Tableau publishes no documentation, no versioning and
no support statement for it, and search found no Tableau page that names it as an API. Whether a REST token still opens
a Vizportal session on Tableau Cloud today is *(verify)*.

**Risks of building on it:**

- **No contract.** Any Server release, or any Cloud update (several a year, and Cloud is never pinned), can rename a
  method or change a payload, and nothing announces it. Error codes are undocumented, so the client can only report
  "VizPortal API threw code N".
- **Session reuse.** Riding the REST token as a web session cookie depends on an implementation detail. A change to CSRF
  or cookie handling breaks it silently.
- **Two id spaces.** Vizportal integer ids and REST LUIDs differ, so mixed use needs extra lookups.
- **The current code disables TLS validation.** `VizPortalClient.buildClient` sets
  `ServerCertificateCustomValidationCallback` to always accept; the `IgnoreSSLErrors` check is commented out. It must
  not ship as it is.
- **Cost of dropping it is low.** It never shipped: 1.2.5 has no Vizportal types. Removing it breaks no nuget.org
  consumer.

**What has a public REST replacement:**

| Vizportal method | Vizportal call | REST replacement |
|---|---|---|
| MoveWorkbook, MoveDatasource | `moveContentToContainer` | Update Workbook or Update Data Source with `<project id>` (2.0) |
| MoveProject | `moveContentToContainer` | Update Project with `parentProjectId` *(verify version)* |
| ChangeDatasourceName | `renameDatasource` | Update Data Source `name` (2.0) |

| ChangeProjectOwner | `setProjectsOwner` | Update Project `owner` (3.21) |
| DeleteWorkbook, DeleteDatasource, DeleteProject | `delete*` | Delete Workbook, Data Source, Project |
| Add and Remove tags (workbook, data source) | `addTagsTo*`, `removeTagsFrom*` | Add and Delete Tags (1.0); Batch Add and Delete Tags in Metadata |
| DeleteGroup, AddUserToGroup, RemoveUserFromGroup | `deleteGroups`, `updateUsersGroupMembership` | Delete Group, Add and Remove User to Group (bulk since 3.21) |

### Q5. Modern .NET client patterns for .NET 10

**Support dates.** .NET 10 is LTS, supported until November 2028. .NET 8 and .NET 9 both end in November 2026, two
weeks from today.

**IHttpClientFactory and typed clients.**

- Register a typed client per Tableau connection with `AddHttpClient<TClient>` (a named client underneath). Typed
  clients are transient, and the handler pool rotates every 2 minutes. Long-lived state therefore goes into a singleton
  keyed by the client name: the token, site LUID, negotiated version and rate-limit back-off. It must not live in the
  typed client or in a `DelegatingHandler`.
- Offer `AddAsKeyed()` for consumers who want `[FromKeyedServices("prod")]`.
- Non-DI users need a factory method. It holds one shared `SocketsHttpHandler` with `PooledConnectionLifetime` set,
  replacing today's new `HttpClient` per request.
- Set `AllowAutoRedirect = false` and follow redirects in code, as TSC does. The automatic handler turns a POST into a
  GET on 301 or 302, which loses a sign-in or publish body. Never follow HTTPS to HTTP.

**Microsoft.Extensions.Http.Resilience (10.11.0).** The standard handler does a lot by default:

- retries 408, 429, 5xx, `HttpRequestException` and timeouts, three times, with exponential back-off and jitter from
  2 s;
- honours `Retry-After` (`ShouldRetryAfterHeader` is true by default);
- times out each attempt at 10 s and the whole request at 30 s;
- adds a circuit breaker and a concurrency limiter of 1,000 permits.

For Tableau, change four things:

- **Retries:** call `DisableForUnsafeHttpMethods()`, then allow back only Sign In and idempotent PUTs. Publish, Create
  and Run Now are not idempotent.
- **Timeouts:** raise them or switch them off per request for downloads, PDF and crosstab exports and publishing. 10 s
  and 30 s break those calls today.
- **429 delay:** Tableau's 429 body carries a hint ("Please retry after 146 second(s)"). Whether it also sends
  `Retry-After` is *(verify)*. Add a delay generator that reads the body when the header is missing.
- **Tableau Cloud limits:**
  - 40,000 REST calls per user per site per hour (Migration SDK docs);
  - extract-refresh API calls per hour per tenant: Standard 120, Enterprise 240 plus 1 per Creator, Cloud+ and Tableau+
    480 plus 2 per Creator;
  - publish API calls per hour per tenant: Standard 800 and up.

  Expose these as typed `TableauRateLimitException` data, and do not retry for an hour.

**DI registration and options.**

- `AddTableauClient(name, Action<TableauClientOptions>)` returns a builder, as in Q3.
- Options bind from configuration (the binding source generator keeps this AOT-safe) and are validated with
  `ValidateOnStart`.
- The secret comes from a delegate, not from an options string, so it can live in a vault.
- Logging goes through `Microsoft.Extensions.Logging.Abstractions` 10.x and the `LoggerMessage` source generator. Never
  log tokens, PAT secrets, JWTs or `X-Tableau-Auth`.
- Drop the `Microsoft.Extensions.Logging` 2.1.1 dependency and Newtonsoft.Json.

**System.Text.Json source generation.**

- One `JsonSerializerContext` covers all models, with `[JsonSourceGenerationOptions]` set to camelCase names,
  `AllowReadingFromString` numbers (Tableau's string-typed numbers, *(verify)*) and `JsonStringEnumConverter<T>` per
  enum. The non-generic converter is not AOT-safe.
- Metadata mode is needed for deserialization. The fast path covers serialization only.
- In .NET 10, the source generator does not support private members. Models should be public records with `init` or
  `required` members.

**Native AOT and trimming: the deciding question.** `XmlSerializer` cannot be made AOT- or trim-safe:

- **Every constructor is annotated.** In dotnet/runtime `main` (last change 2026-04-30), every public `XmlSerializer`
  constructor carries both `[RequiresUnreferencedCode]` (IL2026, "Members from serialized types may be trimmed") and
  `[RequiresDynamicCode]` (IL3050, "XML serializer relies on dynamic code generation which is not available with Ahead
  of Time compilation"). A library with `IsAotCompatible` can only pass these on to every public method, which warns
  every AOT caller, or suppress them, which misstates its compatibility. The repo already suppresses IL2026 and IL2104.
- **Under native AOT, `XmlSerializer.Mode` is forced to `ReflectionOnly`** (`RuntimeFeature.IsDynamicCodeSupported` is
  false). The constructor returns before it ever looks for a pregenerated serializer assembly. That mode may work if
  every member of every model survives trimming, but nothing checks that at build time.
- **`Microsoft.XmlSerializer.Generator` (10.0.14), the modern `sgen`**, emits `Tableau.Api.XmlSerializers.dll` to
  speed up start-up on the JIT runtime. It does not remove the warnings and is ignored under AOT. `sgen` also fails on
  `init` setters, which rules out modern model types.
- **No first-party XML source generator ships in .NET 10** *(verify)*. The other AOT-safe XML route is a hand-written
  `XmlReader` and `XmlWriter` mapping for about 300 types.
- **Microsoft's own advice** for reflection-based serializers is to move to source-generated System.Text.Json.

Result: if trim- and AOT-safety is a goal, the models must move to JSON (decision D1). The library can then set
`IsAotCompatible` and `VerifyReferenceAotCompatibility`.

**IAsyncEnumerable for paged endpoints.**

- **Pages:**
  - `ListAsync(query, ct)` returns `IAsyncEnumerable<T>` and fetches page after page, with `[EnumeratorCancellation]`
    on the token;
  - `ListPageAsync(pageNumber, pageSize, query, ct)` returns `Page<T>(Items, PageNumber, PageSize, TotalAvailable)`
    for callers that page themselves;
  - pages start at 1, with 100 items by default and 1,000 at most where the docs give a limit *(verify per method)*.
- **One enumerable for every paging scheme:** REST `pageNumber` and `pageSize`, Pulse and Vizportal page tokens,
  GraphQL cursors.
- **Ordering.** Tableau warns that, without an explicit `sort`, results follow an internal index, and items can be
  missed if the list changes between pages. Default to a stable sort where the resource has one, and document the
  caveat.
- **LINQ.** In .NET 10 `System.Linq.AsyncEnumerable` is in-box, so callers get LINQ over the results without
  `System.Linq.Async`.

**CancellationToken conventions.**

- Every async member takes `CancellationToken cancellationToken = default`, last (CA1068), and passes it on to every
  call (CA2016). This replaces today's `CancellationToken?`.
- Streams handed to the caller, from downloads and exports, honour the token in `ReadAsync`.
- Timeouts surface as `TimeoutException` or the resilience timeout exception, never as the caller's
  `OperationCanceledException`.

**Nullable annotations.** Turn on `<Nullable>enable</Nullable>` and treat warnings as errors. Generated models mark
optional XML attributes as nullable and required ones as `required`. Public API files
(`Microsoft.CodeAnalysis.PublicApiAnalyzers` 5.6.0) record the annotations, so a PR diff shows any change.

**Target frameworks.**

- **No statistics exist.** nuget.org does not publish consumer target-framework data, so the share of .NET Framework
  users cannot be measured. Its page shows no dependent packages or popular GitHub repos.
- **The known facts:**
  - 1.2.5 is `netstandard2.0`, so it runs on .NET Framework 4.6.1 to 4.8.1;
  - `main` already moved to `netstandard2.1` in 2023, which no .NET Framework app can use;
  - the likely .NET Framework users are Windows PowerShell 5.1 scripts and SSIS script tasks, both common in Tableau
    administration *(verify)*.
- **Recommendation:** net10.0 only (decision D4).
  - The models move to JSON; `netstandard2.0` would need System.Text.Json, `IAsyncEnumerable` and
    Microsoft.Bcl.AsyncInterfaces as polyfill packages.
  - Trimming analysis does not run on `netstandard`.
  - 1.2.5 stays on nuget.org for .NET Framework.
  - Adding `netstandard2.0` later is a minor, non-breaking change if users ask. Removing it later would be a major.

### Q6. Testing without a live server

Four layers, from fastest to slowest:

1. **Unit tests through an `HttpMessageHandler` fake** (RichardSzalay.MockHttp 7.1.0, or a small hand-written handler).
   They assert the request: method, URI, query, `X-Tableau-Auth`, body. They also feed back canned responses and error
   bodies. They cannot test the resilience pipeline, which sits outside the fake.
2. **Contract tests against recorded fixtures replayed by WireMock.Net (2.20.0).**
   - WireMock.Net runs an in-process HTTP server, so the real `HttpClient`, the resilience handler, redirects and the
     session manager all run.
   - Its proxy-and-record mode can capture responses from a live site *(verify the current API)*. Scrub tokens, LUIDs,
     names and emails, and store the result under `tests/fixtures/<apiVersion>/<area>/`.
   - These fixtures are the only contract for the JSON shape (Q1). Re-record them when a new API version ships.
3. **A stateful simulator for multi-step flows** (publish, then list, then delete; sign in again after 401).
   - Tableau's Migration SDK ships one: `Tableau.Migration.Api.Simulation.TableauApiSimulator`, Apache-2.0, over XML.
   - It is a model to learn from, not code to copy; mixing Apache-2.0 code into an MIT package needs its NOTICE kept.
   - For fault injection against the real binary, Microsoft's Dev Proxy can return 429 with `Retry-After`, and slow
     responses.
4. **An opt-in live suite.**
   - **Tableau Server in a Container is not a CI option.**
     - You build the image yourself, from the `.rpm` with the setup tool.
     - Running it needs a licence key.
     - Docker Desktop's default limits are "far below the minimum requirements".
     - Tableau's published minimum hardware is at or above a standard GitHub-hosted runner *(verify)*, and the trial
       terms are *(verify)*.
     - Use it, if at all, by hand for Server-only features: schedules, impersonation, identity pools.
   - **The Tableau Developer Program site still exists.** tableau.com/developer still advertises "your free sandbox".
     - A 2021 Tableau post: one Creator, one Explorer and one Viewer licence, with site admin rights.
     - The terms: content can be updated or wiped at any time; not for heavy workloads; no customer, sensitive or
       production data.
     - Renewal: by an emailed link before expiry; the current interval is *(verify)*.
     - It may run a pre-release Tableau Cloud build *(verify)*, so a failure there can be Tableau's, not the client's.
     - tableau.com returned 403 to automated fetches, so the current terms could not be read directly.
   - **Running it in CI:**
     - a `live` test category that runs only when `TABLEAU_SERVER_URL`, `TABLEAU_SITE` and a credential are set;
     - credentials from environment variables or user-secrets locally, and from a GitHub environment
       (`tableau-live`, with required reviewers) in CI;
     - triggered nightly on `main` and by `workflow_dispatch`, never on pull requests, because GitHub does not pass
       secrets to workflows from forks;
     - run serially, or sign in through a connected app, because one PAT allows one session and a second sign-in ends
       the first. A direct-trust app also avoids the 15-day PAT expiry (its secrets do not expire);
     - prefix every object with the run id, and delete it in cleanup.

**What to copy from TSC:**

1. **Version negotiation.**
   - `Server.use_server_version()` reads Server Info.
   - Each endpoint declares its minimum version (`@api(version=...)`), and `assert_at_least_version` raises a typed
     error before any request.
   - The client's `[ApiVersion]` attribute already exists. Check it against the negotiated version, not a cap of 3.14.
2. **Pager and QuerySet.**
   - Lazy iteration over every page.
   - Django-style filters: `filter(name="x")`, `tags__in=[...]`, `order_by("-createdAt")`, `paginate(page_size=...)`.
   - Typed `Field` names and the operators `eq`, `gt`, `gte`, `lt`, `lte`, `in`, `has` and `cieq`.
   - In .NET: `IAsyncEnumerable` plus a typed filter builder. Today the client takes raw `filterExpression` strings and
     skips URL-encoding them.
3. **Export options as types:** `CSVRequestOptions`, `ExcelRequestOptions`, `ImageRequestOptions`, `PDFRequestOptions`
   and `PPTXRequestOptions`, with view filters, resolution, size and max age.
4. **Publish that picks the method by size:** a single request under 64 MB, chunked above it (50 MB parts by default),
   `as_job`, and a progress callback.
5. **`jobs.wait_for_job(job, timeout)`** with exponential back-off.
6. **Lazy population:** `populate_connections`, `populate_permissions`, `populate_views`, `populate_preview_image`.
7. **Tagging and permissions as mixins**, shared by every content type, instead of one method per type.
8. **Credential types** (`TableauAuth`, `PersonalAccessTokenAuth`, `JWTAuth`) and a sign-in scope that signs out at the
   end; in .NET an `IAsyncDisposable` session.
9. **Redirects followed in code**, keeping method and body, with HTTPS-to-HTTP downgrades refused.
10. **A thread-safe shared server object** whose auth state is an immutable snapshot swapped by reference. In .NET:
    `HttpClient` is already thread-safe, and the session record is swapped with `Interlocked.Exchange`.

What to do better than TSC: async with cancellation, 429 and capacity handling, JSON and AOT, JWT minting through a
delegate, and automatic sign-in again on expiry.

### Q9. Trademark

**The rule.** Salesforce's Trademark and Copyright Usage Guidelines (last updated 2023-06-12) cover Tableau as an
affiliate brand:

- **Names.** Third parties may not put a Salesforce mark "into your company name, app name, product name, service name,
  website or domain name", nor use "a name or brand that may be viewed as being a part or extension of a Salesforce
  trademark family". Their example of a forbidden domain is `www.tableauapp.com`.
- **In text,** a mark may be used if it is not part of the offering's name or branding, is less prominent than the
  offering's name, and follows a referential phrase: "compatible with", "runs on", "built on", "integrates with".
  Nothing may suggest endorsement.
- **Attribution:** "Tableau is a trademark of Salesforce, Inc.", in the credits or end section.
- **Logos:** allowed only inside a diagram, never as the most prominent logo, and never echoed by the project's own
  logo or font.
- "Most uses require specific written permission."

By these rules, `Tableau.Api` as a package id, a namespace and a repo name is a use the guidelines prohibit. The id has
been on nuget.org since 2018 without any objection on record, and similar names are common (TableauAPI,
TryIT.TableauApi, TableauSharp, and the Python tableau-api-lib). That lowers the practical risk but does not remove it.
nuget.org cannot rename an id. If Salesforce objects, the fix is a new id, with the old one deprecated and pointing to
it.

**How open-source Tableau projects word it:**

- `tableau/tableau-metadata-explorer` (a community tool in Tableau's own GitHub org) names itself "Metadata Explorer
  for Tableau" and says: "It is **not affiliated with, endorsed by, or sponsored by Tableau or Salesforce**. "Tableau"
  is a trademark of Salesforce, Inc., used here only descriptively to indicate the product this tool works with."
- `sophonio/sophon-skills`: "Tableau is a trademark of Salesforce, Inc. and/or its affiliates. This skill is an
  independent integration developed by ... and is not affiliated with, endorsed by, or sponsored by Salesforce or
  Tableau."
- `banthia14aman/tableau-builder-mcp`: "Not affiliated with Tableau or Salesforce. Tableau is a trademark of Salesforce,
  Inc."

**Suggested wording.** The first lines of the README, and the end of the package description:

> Tableau.Api is an independent, open-source .NET client that integrates with the Tableau REST API. It is not

## Feature list

Cost: S is up to 3 days, M is 1 to 2 weeks, L is more than 2 weeks. Ranked by value within each tier.

### P1: in 2.0.0

1. **Modern sign-in and a session manager** (M).
   - PAT, connected app JWT (direct trust and OAuth 2.0 trust), UAT, password, and impersonation on Server.
   - JWTs are minted per sign-in through a delegate.
   - Lazy sign-in; one sign-in at a time; sign in again on 401 or on expiry (120 minutes or 30 idle on Cloud, 240 on
     Server); sign-out on dispose.
   - An explicit `TableauSession` stays available for multi-site work and Switch Site.
2. **JSON models generated from the xsd** (L).
   - A generator in `eng/` turns `ts-api_3_29.xsd` into public, nullable, `required`-annotated records with
     `[JsonPropertyName]`.
   - One source-generated `JsonSerializerContext`; `IsAotCompatible`.
   - The multipart publish payload is written with `XmlWriter`.
   - Fixtures recorded per area pin the JSON shape.
   - It replaces the 11,158-line `XmlSchema.cs` and the manual `TableauIDWithMFA` patch.
3. **Transport: IHttpClientFactory, DI and resilience tuned for Tableau** (M).
   - `AddTableauClient(name, ...)`, options validated at start-up, keyed clients.
   - Redirects followed in code; no POST retries; long timeouts for downloads and publishing; a 429 delay read from the
     header or the body.
   - Typed exceptions with Tableau's `code`, `summary` and `detail`, plus `TableauRateLimitException`.
4. **Version negotiation and capability checks** (S).
   - Server Info at start; per method, the minimum version and whether it runs on Server, Cloud or both.
   - Both `/api/{v}/` and `/api/-/` URLs.
   - Known versions up to 3.30.
5. **Paging and filters** (M). `ListAsync` as `IAsyncEnumerable`, `ListPageAsync`, and a typed, URL-encoded filter and
   sort builder.
6. **The Tableau Cloud task model** (M).
   - Create and Update Cloud Extract Refresh Task, Cloud subscriptions with frequency, and the Cloud payloads for
     Get and List Extract Refresh Task.
   - Delete Extract Refresh Task, Add Data Source to Server Schedule, Query Jobs with filters, and
     `WaitForJobAsync(job, timeout)`.
7. **Publishing** (M). Single request up to 64 MB, automatic chunking above it, `asJob`, `IProgress<long>`, and
   cancellation that stops the upload.
8. **Generic permissions and tags** (M). One API over every content type (projects, workbooks, views, data sources,
   flows, virtual connections, collections, databases and tables), plus default permissions. It replaces 22 methods and
   the misfiled `AddWorkbookToSchedule`.
9. **Metadata API (GraphQL)** (S). `QueryMetadataAsync<T>(query, variables)` with a cursor-paging helper; scope
   `tableau:content:read`.

### P2: minors after 2.0.0

10. Custom views (list, get, update, delete, image, data, PDF, default for users), Get View by Path, Download Workbook
    PowerPoint, view filters on exports (M).
11. Flows: query, publish, download, run now, run task, runs, cancel, connections, owner; Cloud flow tasks (M).
12. Webhooks CRUD and test (S).
13. Update Data in Hyper Data Source (JSON actions), Create and Delete extracts (S).
14. Users at scale: bulk group membership, Import and Delete Users with CSV, `email` and `idpConfigurationId` (S).
15. Replace permissions (3.23), Get Server Schedule, server sessions, project owner (S).
16. Metadata REST gaps: single gets, DQW delete and batch, certifications (S).

### P3: on demand

17. Labels, virtual connections, collections, Recycle Bin, content search and usage statistics.
18. Administration: identity pools, OpenID Connect, connected app and EAS management, SCIM, PAT list and revoke.
19. Pulse, in its own area or package, JSON with snake_case names, mostly Cloud only.
20. VizQL Data Service and the Tableau Cloud Manager API.
21. Telemetry: an `ActivitySource` and a `Meter` named `Tableau.Api`, with no tokens and no content names by default.
22. Encrypted keychains and user credentials (migration scenarios).

## Decisions for the maintainer

These are one-way doors. Each is settled before the code that depends on it.

| # | Decision | Recommendation | Trade-off |
|---|---|---|---|
| D1 | **Wire format and models** | JSON through System.Text.Json source generation, models generated from the xsd, `IsAotCompatible` on. XML only for the multipart publish payload, through `XmlWriter`. | Gains trimming, AOT, one serializer for REST, Pulse and GraphQL, and smaller payloads. Costs: no formal JSON schema, so recorded fixtures carry the contract; a less-travelled path than TSC's and the Migration SDK's XML. The alternative, `XmlSerializer` with IL2026 and IL3050 passed on to callers, ships faster but can never claim AOT safety. A hand-written `XmlReader` mapping for 296 types is the costliest. |
| D2 | **API shape** | A client bound to its session: `tableau.Workbooks.ListAsync(...)`, built per connection by DI, with session handling inside. Keep an explicit session API for multi-site work. Breaks every call site. | Today's style (pass `TableauSession` to 142 methods) maps one to one onto the REST reference and is easy to port. The bound client is what DI, resilience and automatic sign-in need. Migrating costs every consumer a rewrite, which a migration guide eases. |
| D3 | **Vizportal** | Drop it from 2.0.0. List the REST replacements (Q4) in the migration guide. If run-schedule-now or bulk calls are wanted, ship them later as a separate `[Experimental]` package after a fresh review, with TLS validation on. | It never shipped, so no package consumer loses anything. Users of `main` lose run-schedule-now and bulk calls. Keeping it ties a supported release to an undocumented API that can break on any Cloud update. |
| D4 | **Target frameworks and the 1.x line** | `net10.0` only. 1.2.5 stays installable for .NET Framework, gets security fixes only until a date in SECURITY.md (for example 2027-06-30), and is marked Legacy once 2.0.0 ships. | No statistics show how many users are on .NET Framework; PowerShell 5.1 and SSIS are the likely ones. They keep 1.2.5 but get no new endpoints. Adding `netstandard2.0` later is a minor change; dropping it later would need a major. |
| D5 | **Version number** | **2.0.0** with SemVer and MinVer, rather than a year line. Adopt WriteableFileProviders' rules for breaks, obsolete members and support. | 2.0.0 already sorts above 1.2.5, and a year line would read as a Tableau release number (2026.3). Cost: the maintainer's packages no longer share one version style. |
| D6 | **Package id and trademark** | Keep the `Tableau.Api` id for continuity. Add the disclaimer and attribution (Q9). No Tableau logo, and no new packages under `Tableau.`. Prepare a fallback id in case Salesforce objects. Optionally ask Tableau's developer relations for written permission. | The guidelines prohibit the mark in product names, so the risk is real but has stood since 2018. A rename now loses search ranking, 70k downloads of history and every existing reference, for a risk that has not materialized. |
| D7 | **Licence** | MIT, agreed in writing with Starschema (nuget.org co-owner, named as `Company`) and László Nemes (20 of the 80 commits, 2022 to 2024, including most of Vizportal). Add `LICENSE` now: the GitHub repo became public today with no licence, which grants nobody any rights. | Until it is settled, nobody can legally contribute or fork. MIT matches WriteableFileProviders and TSC. Apache-2.0 adds a patent grant and NOTICE rules. |
| D8 | **Oldest Tableau version supported** | Test against the Server versions Tableau still maintains (24 months of full support, then 12 of limited support): roughly 2024.2 (REST 3.23) and later as of 2026-10 *(verify the dates)*. Allow older versions if the caller opts in. | A higher floor means fewer version branches. Sites on Server 2022 and 2023 fail with a capability error, or must accept the risk. |
| D9 | **Live test environment and credential** | The free Developer Program site for the nightly suite, with a direct-trust connected app as the CI credential, scoped and in a reviewed GitHub environment. Server-only features are tested by hand. | Free, but terms can change, content can be wiped, and it may run pre-release Cloud builds. A PAT is simpler but allows one session and expires after 15 idle days. A paid site or Server licence costs money. |

## Engineering work

This is not features. It is what makes the repo modern and keeps it that way. The code-review agent's findings slot into
these steps.

- **Solution:**
  - `.slnx`, `src/` and `tests/`;
  - central package management;
  - `net10.0`, nullable, warnings as errors, `AnalysisLevel` latest-recommended;
  - XML docs on every public member;
  - Public API files and package validation (Q8);
  - `IsAotCompatible` and `VerifyReferenceAotCompatibility`.
- **Packaging:** MinVer, Source Link, deterministic CI builds, snupkg, README with the disclaimer, an icon, MIT, GitHub
  URLs (Q8).
- **Tests:**
  - MSTest 4.5 on Microsoft.Testing.Platform;
  - the four layers of Q6, with a `live` category gated on environment variables;
  - a fixture recorder and scrubber in `eng/`;
  - coverage gated per assembly, with floors that rise.
- **CI:**
  - build, unit and contract tests, the AOT publish smoke test (a tiny console app published with `PublishAot`, which
    must report no warnings) and pack, on every PR;
  - the live suite nightly in the `tableau-live` environment;
  - CodeQL and Dependabot;
  - release on a tag, through trusted publishing behind the `release` environment.
- **Launch:** LICENSE, README, CONTRIBUTING, SECURITY with private vulnerability reporting, a migration guide from
  1.2.5, and the GitHub repo description corrected.
